# Fish Audio：一个席位，一次克隆，持续复用

> 历史记录：配置、价格与能力以当时日期为准。当前生产行为及待办见 [项目现状](../CURRENT_STATUS.md)。

2026-10-18 接入。Google 继续识别和翻译，Fish 负责克隆合成；默认网页只上传原素材和选择语言，不需要 Google 的额外录音。

## 席位使用规则

- 只使用一个保存的测试音色，限制为单人素材。首次选好参考后创建一次，换素材也仍用这个声音，不会悄悄克隆新人物。
- 音色记录保存在 `.data/fish-test-voice.json`；后续任务和进程重启复用 `modelId`。这个文件不按结果保留期删除。
- 若设置 `FISH_REFERENCE_ID`，直接使用指定的既有音色。未设置时先查询账号自己已有的音色，有且仅有一个就复用；有多个则要求明确指定，不自行挑选或创建。
- 只有账号没有音色、没有历史创建记录、且已经选好参考片段时，才发一次 `POST /model`，创建 private / fast 音色。
- 创建前先将唯一标题和 `creating` 状态持久写盘并同步目录；文件锁防止多个进程占多个席位。
- 创建响应丢失或进程中断后，按保存的唯一标题查询远端恢复 ID，不自动重复 POST。远端没有匹配、创建失败、音色被删或记录损坏时，都保留现场并报告错误，不自行替换音色。
- 取消、退款、换语言、失败重试、文件清理和反复测试均不删除或重新创建音色。服务端不提供自动删除模型的路径。

因此，“持续复用”也适用于新的测试输入：它验证流程和外语发音，只有输入人物与首次参考相同时，才能用来评估原人物的音色相似度。多人克隆等购买更多席位后再开放。

## 配置与操作

服务端 `.env.local`（不提交 Git，不在页面暴露）：

```dotenv
CLONE_PROVIDER=fish
FISH_API_KEY=your-server-only-key
FISH_TTS_MODEL=s2.1-pro-free
FISH_REFERENCE_ID=
```

测试使用 Fish 官方提供的 `s2.1-pro-free` 开发档；付费 `s2.1-pro` 可以显式配置，程序不会自动切换或代买额度。

```bash
# 只检查现有声音；没有参考参数就不会创建
npm run fish:voice

# 选定一个参考之后才创建；以后相同命令会直接复用
npm run fish:voice -- --reference /path/reference.wav --start 0 --seconds 20

# 用保存的声音跑真实 Google + Fish 流程
npm run benchmark:dubbing -- --input /path/source.wav --mode clone --target es
```

也可直接在网页提交第一个单人视频，由既有参考筛选器自动挑 10–30 秒片段；已保存声音的后续任务无需重新满足参考时长。CLI 的 `--voice-id` 只临时选择一个既有声音做诊断，不创建音色，也不写入默认音色记录。

原文随参考音频一起送 Fish。后续句子只传翻译文本及固定 `reference_id`，不逐句传新参考、不逐句训练。当前选择保留原参考音质，`enhance_audio_quality=false`，避免额外处理改变音色。

## Google 流式识别翻译可行性实测

2026-10-18，当前 `gemini-3.8-flash` 的 Interactions 请求带 `stream: true` 和现有 JSON schema，真实返回 HTTP 200 / SSE。实验按 `step.start` 的 `model_output` 过滤 `step.delta`，只在一个完整分句对象收齐并通过字段/时间校验后，才提交给固定 Fish 音色合成；没有把不完整 JSON 或半句直接交给 TTS。

17.086542 秒参考音频，3 句，单次结果：

| 时点（自 Google 请求前开始计时） | 耗时 |
| --- | ---: |
| 收到 HTTP 响应头 | 8.610 s |
| 第一段文本增量 | 8.616 s |
| 第一完整分句 / 启动第一个 Fish 请求 | 9.452 s |
| Google 整段返回完成 | 10.464 s |
| 首个任意分句音频完成（本次为第二句） | 15.003 s |
| 时间线上首句音频完成 | 15.536 s |
| 全部分句原始音频完成 | 16.560 s |

首个合成请求比等待 Google 完整结果早 1.012 秒。大量等待发生在首个文本增量之前，流式并不能消除这段时间；最后一句生成也可能决定总耗时。因此本次证明了提前合成可行，不能宣称整段稳定提速 1 秒，更不能将 16.560 秒与含网页上传、排队及视频合并的 23.900 秒直接比较。

原始报告：`.runtime/benchmarks/streaming-probe-1792336212852/report.json`。这是首次独立实验，不包括完整网页处理时间。

随后已将 SSE 接入真实 `GoogleProvider` / `dubRecording`，使用 `STREAM_TEXT_PIPELINE=true` 显式开启，默认仍关闭以供对照。仅已有 Fish 音色的单人 clone 路径会提前合成；首次建音色仍等待完整分析和参考选择。流式处理维持三路并发上限、背压和全局取消，最后验证完整 JSON、全部分句与整体说话人/时间线后才发布结果。重复分句不再次合成；失败时等待在途任务退出后才清理目录。新增测试覆盖带转义字符与网络切片的 JSON/SSE、断流、非法时间戳、跨阶段并发和失败后的清理；41 项测试、类型检查与生产构建通过。

官方依据：[Interactions SSE](https://ai.google.dev/gemini-api/docs/streaming)、[结构化输出流式返回](https://ai.google.dev/gemini-api/docs/structured-output#streaming_results)。
